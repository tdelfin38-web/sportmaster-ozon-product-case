# Интеграционный контур FBS

## Роли систем

| Роль | Зона ответственности |
| --- | --- |
| Ozon Seller API | Внешние данные о заказах, статусах, остатках, реализации и возвратах. |
| Интеграционный слой | Маппинг данных, повторы, дедупликация и журнал обмена. |
| Контур управления заказами | Создание и сопровождение внутреннего заказа. |
| Складской контур | Остаток, резерв, сборка, упаковка и готовность к передаче. |
| Учётный контур | Финансовое отражение реализации, услуг и возвратов. |
| Операционное рабочее место | Разбор исключений и ручная обработка расхождений. |
| Мониторинг | Доступность обмена, ошибки и задержки статусов. |

## Функциональные операции

| Операция | Зачем нужна |
| --- | --- |
| Получить новые или изменённые FBS-заказы | Не пропустить заказ и создать внутреннее задание на исполнение. |
| Получить состав и параметры отправления | Проверить товар, количество и требования к обработке. |
| Передать заказ во внутренний контур | Связать внешний заказ с обработкой и складом. |
| Получить маркировочные данные | Подготовить готовое отправление к передаче Ozon. |
| Сформировать или подтвердить отгрузку | Зафиксировать передачу отправлений в логистический поток. |
| Синхронизировать готовность и передачу | Поддерживать согласованный статус заказа во внешнем и внутреннем контурах. |
| Получить статусы, реализацию и возвраты | Обновить заказ, остатки, учёт и работу с возвратами. |
| Сверить данные и обработать исключение | Найти расхождение, исключить дубли и передать проблему оператору. |

## Принцип надёжности

Для операций, которые меняют состояние заказа, нужны повторная обработка временных ошибок, защита от дублей и регулярная сверка внешнего и внутреннего статусов. Конкретный способ обмена выбирается на этапе проектирования с учётом возможностей API и внутренней архитектуры.
